# ARCHITECTURAL SPECIFICATION & ACTION PLAN
## Project: `ComfyUI-Settings-Hub`

---

## 1. Обзор проекта и концепция

**`ComfyUI-Settings-Hub`** — это frontend-ориентированное расширение для ComfyUI, добавляющее настраиваемые интерактивные пульты управления (Хабы настроек) с поддержкой вкладок.

### Ключевые возможности:
1. **Вынос любого параметра в один клик:** Клик ПКМ по любому виджету любой ноды $\to$ `📌 Pin to Settings Hub` $\to$ выбор Хаба и вкладки.
2. **Zero-Wire & Zero-Node архитектура:** Никаких связующих проводов и вспомогательных нод (типа `Get/Set`). Прямая двусторонняя синхронизация значений виджетов в реальном времени через LiteGraph DOM.
3. **Multi-Hub & Multi-Tab:** Поддержка нескольких независимых Хабов на одном холсте, внутри каждого Хаба — неограниченное количество вкладок.
4. **Полная организация полей:** Drag-and-Drop сортировка полей, перенос между вкладками, визуальные разделители (Dividers), переименование и сортировка самих вкладок.
5. **Поддержка 100% типов виджетов:** Числа, слайдеры, текст, промпты, чекбоксы, а также любые динамические комбо-боксы (модели, LoRA, семплеры, кастомные списки сторонних нод).
6. **Система пресетов:** Сохранение и мгновенное переключение снапшотов настроек внутри Хаба.
7. **Телепортация и индикация:** Кнопка `🎯 Locate` перемещает камеру к исходной ноде. На самой ноде отображается ненавязчивый бейдж `📌`.

## 4. Детальная спецификация модулей

### Модуль 1: Backend (`py/settings_hub.py` + `__init__.py`)
* Класс `SettingsHubNode`:
  * `CATEGORY = "Settings Hub"`
  * `RETURN_TYPES = ()` (без выходов)
  * `FUNCTION = "noop"`
  * `INPUT_TYPES`: пустой словарь `{"required": {}}` или опциональный dummy input.
* В `__init__.py` прописать `WEB_DIRECTORY = "./web"`.

### Модуль 2: Context Menu Hook (`web/context_menu.js`)
* Перехватывать контекстное меню клика по нодам / виджетам в LiteGraph.
* Проверять, под каким виджетом был сделан клик.
* Добавлять пункт `📌 Pin to Settings Hub ➔`:
  * Находить все экземпляры `SettingsHubNode` на холсте (`app.graph._nodes`).
  * Для каждого Хаба рендерить подменю со списком его вкладок + пункт `[ ➕ Add to New Tab ]`.
  * Если Хабов на холсте нет: показывать пункт `[ ➕ Create New Settings Hub ]`.
* При клике: вызывать `SyncManager.createBinding(hubNode, targetNode, widget, tabId)`.

### Модуль 3: Hub UI & Rendering (`web/hub_ui_renderer.js` + `web/hub_node.js`)
* Кастомный размер ноды Хаба (фиксированная или настраиваемая ширина, автовысота).
* **Tab Bar (Шапка вкладок):**
  * Горизонтальный список вкладок с активным состоянием.
  * Кнопка `[ + ]` для создания вкладки.
  * `DblClick` по вкладке $\to$ инлайн `<input>` для переименования.
  * Кнопка `✕` для удаления вкладки (с диалогом переноса оставшихся элементов).
* **Item Container (Область виджетов):**
  * Рендерить только элементы текущей `activeTabId`, отсортированные по полю `order`.
  * Для каждого элемента рендерить строку:
    * `[⠿]` Ручка Drag-and-Drop.
    * `[Кастомный Лейбл]` (с возможностью редактирования).
    * `[Зеркальный виджет]` (полнофункциональный UI: Slider, Combo, Textarea, Toggle, Number).
    * `[🎯]` Кнопка фокусировки камеры на исходной ноде.
    * `[⚙️]` Меню опций (`Move to Tab`, `Rename`, `Remove / Unpin`).
* **Разделители (Dividers):**
  * Тонкая горизонтальная линия с кастомным заголовком секции.

### Модуль 4: Двусторонняя реактивность (`web/sync_manager.js`)
* **Hub $\to$ Target Node:**
  * При изменении значения в виджете Хаба:
    ```javascript
    const targetNode = app.graph.getNodeById(binding.targetNodeId);
    if (targetNode) {
      const w = targetNode.widgets?.find(x => x.name === binding.widgetToBind);
      if (w && w.value !== newValue) {
        w.value = newValue;
        if (w.callback) w.callback(newValue);
        app.graph.setDirtyCanvas(true, true);
      }
    }
    ```
* **Target Node $\to$ Hub:**
  * Добавлять обертку (hook) на `targetWidget.callback`:
    * При ручном изменении значения на целевой ноде находить все привязанные Хабы и обновлять их зеркальные виджеты.
  * Использовать флаг `isSyncing` для предотвращения бесконечной циклической рекурсии.

### Модуль 5: Drag-and-Drop & Reordering (`web/dnd_manager.js`)
* **Сортировка внутри вкладки:**
  * Обработка событий `dragstart`, `dragover`, `drop` для элементов списка.
  * Визуальный плейсхолдер при перетаскивании.
  * Пересчет индексов `order` и немедленный ре-рендер DOM ноды.
* **Перенос на другую вкладку:**
  * Поддержка `drop` элемента прямо на кнопку целевой вкладки в шапке.
  * Смена `item.tabId = targetTabId`, установка `order = max + 1`.
* **Сортировка самих вкладок:**
  * Перетаскивание кнопок вкладок в шапке влево/вправо с обновлением `tab.order`.

### Модуль 6: Пресеты (`web/preset_manager.js`)
* UI в шапке Хаба: `Preset: [ Default v ] [ 💾 Save ] [ ➕ New ] [ 🗑️ ]`.
* `Save`: считывает текущие значения всех биндингов Хаба и сохраняет в `hubConfig.presets[name]`.
* `Apply`: проходит по биндингам и применяет значения сразу во все целевые ноды.

## 6. Граничные случаи и правила безопасности (Prompt Constraints)

1. **Безопасность типов комбо-боксов:** Проверять тип `options.values`: если это функция (как у некоторых динамических нод), вызывать ее `widget.options.values()`, иначе брать массив напрямую.
2. **Удаление вкладок с элементами:** При удалении вкладки обязательно запрашивать: перенести элементы в первую доступную вкладку или удалить их.
3. **Целостность графа:** Никогда не модифицировать внутренние связи (links) LiteGraph — работать исключительно с объектами `node.widgets`.
4. **Undo/Redo:** Вызывать `app.graph.setDirtyCanvas(true, true)` при любых изменениях значений, чтобы ComfyUI фиксировал историю изменений.
