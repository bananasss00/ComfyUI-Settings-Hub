## 1. Как устроен Paste Stack у Nougan (база для сравнения)

Плавающая панель истории буфера обмена; не-нода, чистое web-расширение
(`web/nougan_paste_stack.js`, 1212 строк + CSS + `nougan_paste_stack_server.py`).

| Механика | Реализация у Nougan |
|---|---|
| Захват | клик по paste-области / Ctrl+V по ховеру → `navigator.clipboard.read()` (текст + изображения); drag файлов на панель |
| Файлы из Проводника | браузер их не видит → python-хелпер `POST /nougan/paste_stack/clipboard` (заголовок `X-Nougan-Paste`, только запросы с той же машины, Pillow читает буфер ОС; Windows: PowerShell-fallback; ≤10 файлов / 60 МБ суммарно / 25 МБ на файл) |
| Возврат в буфер | клик по карточке → `clipboard.writeText` / `ClipboardItem("image/png")`; файловые карточки только скачиваются |
| Drag в ноду | изображение тянется на Load Image: `POST /upload/image` → имя вставляется в combo `image` → `w.callback()`; нода под курсором подсвечивается, Esc отменяет |
| Хранение | IndexedDB (переживает перезагрузки ComfyUI и браузера), UI-стейт в localStorage; лимит 50 (5–500); дедупликация «переместить наверх» |
| UI | drag хедера, ресайз, минимизация в чип с бейджем-счётчиком, WebGPU-фон с CSS-fallback |

**Ограничения оригинала** (пространство для «круче»): только текст / изображения /
текстовые файлы; видео/аудио — карточки «только скачать»; нет поиска, тегов,
избранного, экспорта; нет связи с виджетами воркфлоу; хранение per-origin
(`localhost:8188` ≠ `127.0.0.1:8188`); Clipboard API требует localhost/https.

## 2. Видение: Stack в Settings Hub

### 2.1. Принципы

1. **Отдельная плавающая панель (решение владельца, 2026-11-08)** — НЕ вкладка
   хаба: панель стека живёт поверх канваса независимо от хаба, чтобы работать
   с хабом и стеком одновременно. Своя механика уже есть в проекте: драг хедера,
   ресайз за угол, сворачивание в чип с бейджем-счётчиком (как у Nougan),
   позиция/размер в localStorage. Опционально позже — примагничивание к краям.
2. **Переиспользовать инфраструктуру хаба**: медиа-превью (S/M/L/XL, autoplay),
   пикер/галерея/фуллскрин для карточек, тосты, gear-настройки (новая секция
   «Stack»), движок хоткеев (v67), MirrorSync для вставки в зеркала.
3. **Уникальность против Nougan — интеграция с зеркалами** (см. 2.2).

### 2.2. Киллер-фичи сверх оригинала

1. **Вставка в виджет хаба** — у текстовой карточки кнопка «→ в строку»:
   вставка в последнее сфокусированное зеркальное текстовое поле; плюс drag
   карточки прямо на строку хаба. У Nougan вставка только через системный буфер.
2. **Шаблоны с подстановками — ОТКЛОНЕНЫ владельцем (паркованы).** Оставлено
   здесь как пояснение идеи на будущее: плейсхолдеры `{{имя зеркала}}` заменяются
   при вставке текущими значениями зеркал, пример:

   | Что сохранено в карточке | Что вставится сегодня | Что вставится завтра (после смены seed/сэмплера) |
   |---|---|---|
   | `portrait_{{seed}}_{{sampler_name}}_s{{steps}}` | `portrait_8734658723_dpmpp_2m_s28` | `portrait_193042117_euler_2m_s12` |

   Если владелец вернётся к идее — реализация локальна и выключаема.
3. **Постоянные сниппеты** — пин карточки (не стареет при переполнении),
   переименование, теги, поиск, сортировка «недавние / часто используемые»
   (счётчик использований).
4. **Цвета и ссылки** — hex/rgb в скопированном тексте → цветной чип с копированием
   цвета в один клик; URL → карточка с favicon/превью.
5. **Видео и аудио** — карточки с превью через objectURL (галерея уже умеет
   video/audio); действия «скачать» и «в медиа-строку» вместо невозможного
   copy-back (браузер не умеет класть файлы в буфер).
6. **Стек ↔ очередь** — «Queue с этим изображением»: drop карточки на
   batch-пикер / медиа-строку хаба.
7. ~~Экспорт/импорт~~ — **не нужен**: при хранении на сервере (§2.3.1) стек
   живёт в папке ComfyUI и переносится вместе с ней (копирование папки =
   бэкап и перенос).
8. **Watcher-режим (опция, off по умолчанию)** — автозахват всего копируемого;
   вручную — как у Nougan (клик / Ctrl+V по ховеру).
9. **Глобальный хоткей панели** (движок v67) + Ctrl+V по ховеру как у Nougan.

### 2.3. Архитектура

- `web/stack.js` — новый модуль (штамп `__SettingsHubBuild`, self-report):
  захват, хранение, рендер вкладки; карточки — objectURL с ревокацией.
- Вкладка в `hub_ui_renderer.js` (рядом с Navigate); списка до ~500 карточек
  хватает без виртуализации.
- `py/clipboard_helper.py` — `POST /settings_hub/clipboard` по образцу
  `media_list.py` (прецедент серверного роута в SH уже есть): только loopback,
  заголовок `X-SettingsHub-Clipboard`, Pillow (+ PowerShell-fallback на
  Windows), лимиты как у Nougan. Нода остаётся стабом, роут от очереди не зависит.

#### 2.3.1. Хранение: на стороне ComfyUI-процесса (решение владельца)

В отличие от Nougan (IndexedDB браузера) стек живёт **в файловой системе
ComfyUI** — в userdata-каталоге, поэтому он портабелен: переезжает вместе
с папкой ComfyUI на другую машину/диск, одинаков для `localhost`, `127.0.0.1`
и LAN-доступа, для любого браузера и профиля, переживает очистку site-data
и приватные окна. Браузер — тонкий клиент, сервер — источник истины.

```text
<ComfyUI>/user/default/settings_hub/stack/
├── index.json          # метаданные: [{id, type, name, tags[], pinned, uses,
│                       #             created, text? (инлайн ≤100 КБ), file?}]
└── items/              # блобы: <id>.png/.jpg/.txt/... (≤25 МБ на элемент)
```

- **Роуты** (тот же `py/stack_store.py`-блок, стиль `media_list.py`):
  `GET /settings_hub/stack` (index+метаданные), `POST /settings_hub/stack/item`
  (multipart или raw-body + query-параметры), `DELETE /settings_hub/stack/item/<id>`,
  `POST /settings_hub/stack/patch` (переименование/теги/пин/uses/reorder).
- **Синхронизация**: чтение index при открытии вкладки и на window-focus;
  каждая мутация уходит на сервер сразу; последняя запись побеждает
  (last-write-wins) — конфликтный мерж не нужен.
- **Лимиты**: до 500 элементов и ~200 МБ суммарно (настраивается); при
  переполнении вытесняются самые старые НЕ-пиннутые; текст ≤1 МБ (инлайн
  в index до 100 КБ, дальше — файлом).
- **UI-стейт** (позиция окна, размер превью, фильтры) — по-прежнему в
  localStorage `settingshub.stack.*`: это косметика, терять не жалко.
- **Деградация**: нет python-роутов (не перезапускали ComfyUI после обновления)
  → захват работает в памяти на текущую сессию + баннер «стек не сохраняется,
  перезапустите ComfyUI»; Ctrl+V/клик не зависят от сервера.

- Настройки в gear popup, секция «Stack»: лимит записей/объёма, размер превью,
  watcher, хоткей, кнопка полной очистки (сносит папку items + index).

### 2.5. Риски

- **Clipboard API** требует localhost/https — на LAN-http остаются Ctrl+V и
  хелпер; задокументировать в README (как у Nougan).
- **Серверное хранение**: контроль диска (лимиты + полная очистка в настройках);
  мульти-вкладка — last-write-wins, допускаем потерю параллельной правки
  (приемлемо для стека); userdata-каталог может быть нестандартным —
  использовать `folder_paths.get_user_directory()`, не хардкодить путь.
  Плюс: jsdom-харнесс упрощается — вместо мока IndexedDB мокается `api.fetchApi`.
- **Безопасность**: чтение буфера ОС и запись в userdata — только по запросу
  со страницы, только loopback + кастомный заголовок + лимиты; никаких
  фоновых опросов.
- **Drag в LiteGraph**: pointer capture + подсветка ноды под курсором — схема
  Nougan проверена, конфликтов с канвас-драгом нет; маркеры навигации SH
  используют свой pointer-путь — не пересекаются (карточка drag'ается с панели,
  не с канваса).
- **Регресс-щит**: smoke_nav (220) и smoke_menu (24) не должны измениться;
  вкладка Stack не трогает существующие вкладки.
