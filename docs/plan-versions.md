# План v82 — версии одним источником (single-source version)

Статус: РЕАЛИЗОВАНО в v82 (2026-11-09).
Контекст: репорты владельца «с каждой обновой меняются все файлы проекта из-за
номера версии» и «не вижу tools/version.py в zip v81». Сессия v79–v81 потеряна
(песочница откатилась к v78) — этот документ защищает план от повторной потери.

## 1. Диагноз (почему все файлы меняются каждый релиз)

Сейчас штамп версии лежит В КАЖДОМ web-модуле: guard
`if (globalThis.__SettingsHubBuild !== "vNN") console.error("STALE BUILD: ...")`.
Каждый релиз hand-бампит 10+ файлов. Последствия:

- diff релиза = ВСЕ файлы, даже если функционально изменился один;
- hand-бамп ошибочен: в v78 у всех 10 модулей в ТЕКСТЕ ошибки остался v77
  при штампе v78 (rg "STALE BUILD" web/) — живое доказательство проблемы;
- потерянная сессия v81 делала инструмент, который ШТАМПУЕТ все файлы
  автоматически — это автоматизация проблемы, а не её решение. Владелец прав.

## 2. Решение v82 (принцип: файл отличается между релизами ⟺ файл изменён)

1. Версия-литерал живёт ТОЛЬКО в трёх местах:
   - `web/settings_hub.js` — баннер `web build: vNN`, `__SettingsHubBuild = "vNN"`,
     `styles.css?v=NN`;
   - `py/stack_store.py` — `STACK_SERVER_VERSION = "vNN"`;
   - `README.md` — бейдж `web%20build-vNN`.
2. Guard `__SettingsHubBuild !== "vNN"` в 10 подмодулях УДАЛЯЕТСЯ полностью.
   Остаётся self-report с версией ПОСЛЕДНЕГО ФУНКЦИОНАЛЬНОГО изменения файла:
   `globalThis.__SettingsHubLoaded["stack"] = "v80";` — меняется только когда
   меняется сам файл (это ченджлог файла, а не номер релиза).
3. Entry получает манифест ожиданий рядом с FILES:
   `const EXPECTED = { sync: "vNN", pins: "vNN", ..., stack: "v80", ... };`
   и после импортов сверяет `__SettingsHubLoaded` с EXPECTED: рассинхрон
   именует файл в F12 (устаревший кэш браузера ловится КАК И РАНЬШЕ, причём
   в обе стороны — модуль старше/новче entry).
4. Что НЕ трогается: health-проба web↔py (mismatch-детект уже работает и
   остаётся единственным местом сравнения web vs py), тихие зелёные заметки
   (v78), fail-open регистрация (v66/v67).
5. Инструменты (tools/ входит в zip начиная с v82):
   - `tools/version.py vNN` — механический бамп трёх мест из п.1;
     `tools/version.py --check` — аудит: ровно один литерал в entry/py/README,
     бейдж == штампу, манифест entry == self-report модулей, НИКАКИХ других
     `vNN`-guard'ов. Exit 1 при рассинхроне.
   - `tools/compare.py` — сверка установленной папки custom_nodes с новым zip:
     SAME/DIFFERS/NEW/EXTRA по файлам + версии обеих сторон + советы
     (RESTART при изменении py/, Ctrl+F5 при web/). Ответ на классический
     «а что реально поменялось и что у меня стоит?».
6. Итоговый diff релиза: изменённые файлы + entry (манифест/баннер/штамп/css)
   + 1 строка py + бейдж README. Остальные модули — байт-в-байт прежние.

## 3. Процедура релиза (с v82)

1. Правки кода; если файл функционально изменён — обновить его self-report
   `__SettingsHubLoaded["name"] = "vNN"` и его строку в EXPECTED entry.
2. Тесты (4 набора), все зелёные.
3. `python3 tools/version.py vNN` (бамп баннера/штампа/css/py/бейджа) +
   руками — prose баннера (ченджлог) и README-раздел, если нужно.
4. `python3 tools/version.py --check` — аудит зелёный.
5. zip: git archive → tar → rm tests, .gitignore → zip; В СОСТАВЕ — tools/.
6. Коммит + `Commit: <hash> <title>` в ответе.

## 4. Миграция (шаги v82 поверх восстановленного v79–v81 кода)

1. Удалить 10 guard-блоков `!== "vNN"`; в каждом модуле заменить на
   self-report с версией последнего изменения файла.
2. Entry: добавить EXPECTED + сверку после импортов (сообщение: имена файлов
   + обе версии + Ctrl+F5), удалить упоминание "self-report as v74" (v78).
3. `tools/version.py --check` должен стать зелёным без WARN о guards.
4. Прогнать 4 набора тестов (smoke_stack/smoke_nav/smoke_menu/py) — тесты,
   проверяющие guard-литералы в исходниках, перевести на EXPECTED-манифест.
5. README + AGENTS.md 5.1/6: новая конвенция версий, tools/ в составе zip.
